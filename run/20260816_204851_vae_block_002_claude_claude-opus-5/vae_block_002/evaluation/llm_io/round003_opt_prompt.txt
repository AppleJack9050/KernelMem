#### General engineering experience (applies to every task)

- **a-hung-build-is-usually-a-stale-lock-not-your-kernel** [measured] A killed compile orphans torch's extension baton permanently, and any later kernel reusing that extension NAME hangs on the dead lock and is then misreported as an illegal memory access or an infinite loop.

A directory was found holding a lock from a previous day with no .so and no .o, and the perfectly good kernel that later picked that name was scored -inf and sent to repair.

  - so: If a kernel hangs at build time, suspect a stale baton for its extension name before rewriting the kernel. Give each variant a distinct extension name.

- **a-recorded-method-list-is-advice-not-a-menu** [measured] The best kernel found on a problem is frequently produced by a method absent from the catalog, so treating recorded knowledge as the permitted set forbids the win.

  - evidence: The best kernel to date on one task used `stream_pipeline_overlap`, which is not among the catalog's 26 entries, and it was found in a round where the decision table matched nothing and the judge was free to invent.

  - so: Use the catalog to recognise a fitting method, not to bound the search. If nothing listed fits the measured bottleneck, invent one and name its mechanism.

- **derate-algorithmic-wins-by-the-execution-unit** [measured] An op-count reduction is only realisable at the rate of the units that will execute it; fp32 has no tensor-core MMA instruction at all.

  - evidence: fp32 Winograd F(2x2,3x3) removes 2.25x of the multiplies but runs on CUDA cores at 62.7 TFLOP/s against 105.9 for TF32, so the effective ratio is ~1.33x. On an H100 the same derate is harsher (~3.7x).

  - so: Multiply any op-count win by (achievable rate of the units you will land on) / (rate the baseline uses) before believing it. Quoting the raw ratio funds work that cannot arrive.

- **find-the-dominant-op-before-choosing-a-transform** [measured] Amdahl decides the ceiling before any kernel is written: if one vendor call is most of the GPU time, fusing everything around it cannot pass 1/(1-share).

  - evidence: Measured repeatedly here: a block whose vendor conv was 74-76% of GPU time capped a keep-the-vendor approach at 1.11-1.13x, while owning the operator opened 1.55x. A lineage was once funded on a ceiling no admissible implementation could reach because the share was assumed rather than profiled.

  - so: Profile the reference and state the dominant op's share of GPU time before proposing anything. If the plan keeps that op, say what ceiling it accepts.

- **only-pinned-clock-numbers-are-comparable** [measured] An unpinned GPU clock makes two timings of the same kernel two different experiments, and can produce scores the roofline cannot explain.

  - evidence: Roofline constants here bake in a fixed frequency (104.8 TFLOPS = 170 SM x 256 FLOP/clk x 2.41 GHz). Running at the card's own ~2763 MHz once produced 1.036 -- faster than the light the same constant defines.

  - so: Do not reason about, or compare against, a measurement whose artifact is stamped `locked: false`.

- **rank-on-a-paired-measurement-never-on-score** [measured] A ratio against a separately timed reference is unfit for deciding whether an edit helped; only a paired side-by-side on the kernel's own time is.

template <typename Conv>
static void run_conv_t(const float* xp, const float* wp, float* yp,
                       int N, int H, int W, int C, int K, const torch::Tensor& proto) {
    cutlass::conv::Conv2dProblemSize problem(
        {N, H, W, C}, {K, 3, 3, C}, {1, 1, 1, 1}, {1, 1}, {1, 1},
        {N, H, W, K}, cutlass::conv::Mode::kCrossCorrelation, 1);
    using E = cutlass::tfloat32_t;
    cutlass::TensorRef<E, cutlass::layout::TensorNHWC> ra(
        reinterpret_cast<E*>(const_cast<float*>(xp)),
        cutlass::layout::TensorNHWC::packed({N, H, W, C}));
    cutlass::TensorRef<E, cutlass::layout::TensorNHWC> rb(
        reinterpret_cast<E*>(const_cast<float*>(wp)),
        cutlass::layout::TensorNHWC::packed({K, 3, 3, C}));
    cutlass::TensorRef<float, cutlass::layout::TensorNHWC> rc(
        yp, cutlass::layout::TensorNHWC::packed({N, H, W, K}));
    typename Conv::Arguments args(problem, ra, rb, rc, rc, {1.0f, 0.0f});
    Conv op;
    TORCH_CHECK(op.can_implement(args) == cutlass::Status::kSuccess, "conv can_implement failed");
    size_t ws = op.get_workspace_size(args);
    auto wsb = torch::empty({(long)ws + 1}, proto.options().dtype(torch::kUInt8));
    TORCH_CHECK(op.initialize(args, wsb.data_ptr()) == cutlass::Status::kSuccess, "conv init failed");
    TORCH_CHECK(op(at::cuda::getCurrentCUDAStream()) == cutlass::Status::kSuccess, "conv run failed");
    C10_CUDA_KERNEL_LAUNCH_CHECK();
}

static void conv3x3(const float* xp, const float* wp, float* yp,
                    int N, int H, int W, int C, int K, const torch::Tensor& proto) {

    run_conv_t<typename MakeConv<GemmShape<128,64,16>, GemmShape<64,32,16>, 4>::Op>(
        xp, wp, yp, N, H, W, C, K, proto);
}
